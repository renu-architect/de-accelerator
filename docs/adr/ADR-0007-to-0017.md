# ADRs — Revision 1 (status: APPROVED DIRECTION; Rev 1 pending final approval → then ACCEPTED/Baseline v1.0)

## ADR-0007 Release-versioned insert-only configuration and immutable run snapshots
Context: need CI-validated, atomically activated, auditable config. Decision: Git packs → CI → bundle → loader stages rows under `pack_release_id` (insert-only, `appendOnly`) → activation by single conditional pointer update (`cfg_active_release`) → per-run immutable `run_config_snapshot` (content-hash id). Env overrides resolved at load. Runtime reads snapshots only. Consequences: atomic activation/rollback by pointer flip; supersedes SCD2-in-place wording of doc 02. Alternatives: in-place SCD2 (non-atomic across tables), direct edits (rejected).

## ADR-0008 Repository model and compatibility
Decision: one core repo (SemVer wheel, signed) + one deployment repo per client (bootstrap YAML, packs, approved extensions, tfvars). Extensions only via published interfaces + passing contract tests + entry-point registration; no core patches. Compatibility: MINOR/PATCH backward compatible for packs and runtime schemas; MAJOR with migrations and ≥1 MINOR deprecation window; `requires_core` range in pack; schema version gate at start. Consequences: N client repos to upgrade; clear ownership.

## ADR-0009 Durable batch manifests, idempotent writes, confirmed-commit watermarking (supersedes ADR-0004 details)
Decision: see doc 08. Immutable manifest planned before read (deterministic window, `batch_seq=committed_seq+1`, insert-if-absent), append-only event log, target receipts verified against Delta log (`txnAppId/txnVersion`, commit `userMetadata`), conditional watermark/cursor updates, **per-layer cursors** (source watermark after confirmed Bronze commit; Silver/Gold cursors after their own commits), recovery matrix per state, mandatory crash-injection matrix with invariants I1–I7. Consequences: effectively-once; more tables; Spike S1 (M2) validates MERGE-commit tagging. Alternatives: single FSM across layers (couples extraction to downstream failures), external transaction coordinator (extra infra).

## ADR-0010 Deployment topologies and Terraform
Decision: default ISOLATED (DEV/QA/PROD workspaces); `topology` variable offers NONPROD_SHARED and SINGLE_WORKSPACE; cost options as variables; Terraform modules, remote replicated state, plan-in-CI/apply-by-approval; Databricks Asset Bundles for workloads. Consequences: cost/isolation selectable without code forks; shared topologies need strict UC grants and are documented as reduced isolation.

## ADR-0011 Orchestration provider interface
Decision: framework owns plan/DAG/retry/restart semantics/state; `OrchestrationProvider` translates to a scheduler; `DatabricksWorkflowsProvider` is the only MVP implementation; conformance suite defined. Supersedes ADR-0005 wording (ADR-0005 otherwise stands).

## ADR-0012 Erasure propagation, retention and suppression
Decision: subject-key mapping + lineage-driven erasure tasks across all layers/derived datasets; HMAC-token suppression list consulted by ingestion/reprocess/restore; physical purge (REORG/VACUUM with deletion retention override); evidence tables with counts/versions only; retention policies as metadata; external consumers registry. Consequences: deletion SLA depends on purge/vacuum; backups lag documented; legal determination stays with the client.

## ADR-0013 Backup and disaster recovery
Decision: tiered RPO/RTO **design targets** (doc 11 §4), metadata rebuildable from Git, Delta `RESTORE`/clones, Terraform recreation, post-restore consistency protocol (`verify-consistency`, audited `rewind-watermark`, suppression replay), scheduled DR tests; measured values replace targets only after drills.

## ADR-0014 Document processing: provider interfaces, Azure AI Document Intelligence default
Decision: unstructured is a first-class source kind in the architecture; `OcrProvider/DocumentExtractor/Classifier/EmbeddingProvider/VectorIndexer` interfaces; default OCR `AzureDocumentIntelligenceProvider` (MI/KV auth, private endpoint, budget caps); raw originals immutable; advanced processing + RAG deferred (V1/V2).

## ADR-0015 Semantic outputs and Power BI deployment validation
Decision: generate Databricks SQL views, UC metric views and Power BI TMDL from metadata; tiered validation T1–T5 including real deployment to a test Power BI/Fabric workspace and DAX result validation. TMDL cannot reach COMPLETE without T3–T5 evidence (needs capacity/tenant enablement). Never auto-deploy to PROD BI.

## ADR-0016 Metadata UI outside MVP; UI-ready service interfaces
Decision: Git + PR approval is the only change path in MVP. `MetadataService` library façade (validate/diff/query/propose-to-Git) and versioned JSON-Schemas form the stable contract for a future UI; UI never writes Delta directly.

## ADR-0017 Sizing as design targets
Decision: 500–5,000 objects and ≤10 TB per client are design targets driving defaults; claims require measured scalability/performance tests (doc 10 §5); limits are not guaranteed.
