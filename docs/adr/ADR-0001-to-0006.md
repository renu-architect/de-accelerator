# Architecture Decision Records
Status (Rev 1): ADR-0001 ACCEPTED · ADR-0002 ACCEPTED (refined by ADR-0007) · ADR-0003 ACCEPTED · **ADR-0004 SUPERSEDED IN PART by ADR-0009** (batch FSM/watermark details; the principle "no advance before confirmed commit" stands) · ADR-0005 ACCEPTED (provider wording amended by ADR-0011) · ADR-0006 ACCEPTED (snapshot detail in ADR-0007). Final Baseline v1.0 status is confirmed upon approval of Rev 1. Original text below is preserved unchanged for history.

Format: Context · Decision · Consequences · Alternatives.

## ADR-0001 Independent per-client deployment (no central multi-tenancy)
Context: strict isolation required. Decision: one product, one deployment per client (own Azure env). `client_id` exists in metadata for portability only. Consequences: no cross-client sharing, N upgrades; simpler security. Alternatives: central multi-tenant (rejected by brief).

## ADR-0002 Delta tables as runtime metadata store; Git "metadata packs" as change-control source (needs Q1 approval)
Decision: authoring in Git, validated in CI, loaded to Delta with versioning/history; runtime reads Delta only; YAML only bootstrap. Consequences: reviewable promotion; two representations to keep in sync (loader is the single bridge). Alternatives: direct table edits (no audit), YAML runtime (rejected by brief).

## ADR-0003 Plugin architecture via interfaces + registry/entry points
Decision: Connector, LoadStrategy, DqRule, ReconCheck, Transform, Extractor, SemanticGenerator interfaces; contract tests per interface. Consequences: extensibility without core edits; interface changes are MAJOR. 

## ADR-0004 Watermark commit protocol (no advance before target commit)
Decision: batch FSM `STARTED→READ→TARGET_COMMITTED→WM_COMMITTED→DONE`. Candidate watermark computed from read data and stored in `run_batch`; target writes idempotent via `(object, batch_id)` (Delta `txnAppId/txnVersion` for appends, MERGE on keys, `replaceWhere _batch_id`); only then `wm_watermark` updated with optimistic precondition on `committed_batch_id`. On restart, `TARGET_COMMITTED` batches finish the watermark commit without re-read. Consequences: at-least-once read, effectively-once write; lookback windows tolerate late data. Alternatives: advance on read (rejected), external transaction log (extra infra).

## ADR-0005 Execution via Databricks Workflows with framework planner
Decision: planner builds DAG from metadata and snapshots config; jobs generated via Asset Bundles; parallel objects through `for_each`/task groups with concurrency cap; framework owns retry/restart semantics and records state in Delta. Consequences: native platform ops; limits on task counts → object grouping. Alternatives: in-process thread pool (less visibility), ADF/Airflow (future adapter).

## ADR-0006 Separation of static config and runtime state; frozen run snapshot
Decision: `cfg_*` versioned/SCD2 + history; runtime tables append-mostly; engines read `run_config_snapshot`. Consequences: reproducible runs and restarts; snapshot storage overhead minimal.
